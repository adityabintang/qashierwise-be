## Phase 4: AI Agent — Delivery Flow (set_delivery_type as LLM Tool)

### 4.1 New Tool: `set_delivery_type`
Parameters: `{ delivery_type: "pickup"|"delivery", address?: string, notes?: string }`

Behavior:
- Stores `delivery_type` in conversation's `order_context`
- If `delivery` and `address` provided → stores address in context
- If `notes` provided → stores notes in context
- Returns confirmation message with delivery details

### 4.2 Modify `confirm_order` tool
- Check `aiAgent->isDeliveryEnabled()`:
  - If ON but no `delivery_type` in context → return message instructing AI to ask pickup/delivery first
  - If `delivery` type → add `ongkir` from `aiAgent->default_ongkir` to the pending order
  - If `pickup` → set ongkir = 0
- Include delivery info in confirmation summary

### 4.3 Modify `get_cart_summary` tool
- When `delivery_enabled` and delivery_type is `delivery` in context → add ongkir line to cart summary

### 4.4 Modify `confirmAndCreateOrder()` in AiAgentService
- Read `delivery_type`, `alamat`, `ongkir`, `catatan` from conversation context
- Pass all fields to `OrderService::create()`
- Ongkir is included in the total (via calculateTotals update)

### 4.5 `app/Services/AiAgentPromptBuilder.php`
When `delivery_enabled` is true, append to the system prompt:
```
DELIVERY: Ask "Pickup atau Delivery?" before confirm_order.
If delivery→ask address→add ongkir Rp{X}→use set_delivery_type tool.
If pickup→skip address→ongkir=0.
Ask optional notes (catatan). Then confirm_order.
```

### 4.6 `config/ai_agent_prompts.php`
Add:
```php
'delivery_workflow' => 'DELIVERY: Before confirm_order, ask Pickup/Delivery. If delivery→ask address, add ongkir Rp:ongkir via set_delivery_type. If pickup→skip. Ask optional catatan.',
```

```php
// After finding the AI agent, check if AI is active for THIS contact
if ($aiAgent && $type === 'text') {

        Log::info('AI disabled for this contact, skipping', [
            'contact_id' => $contact->id,
        ]);

    }
    
    ProcessAiAgentMessage::dispatch(...)->onQueue('ai-agent');
}
```

### 5.2 New API Endpoint — Toggle per-contact AI
**Route:** `PUT /api/whatsapp/contacts/{id}/toggle-ai`

**Controller:** `WhatsAppController@toggleContactAi`

```php
public function toggleContactAi($contactId): JsonResponse
{
    $contact = WhatsAppContact::findOrFail($contactId);
    $contact->ai_active = !$contact->ai_active;
    $contact->save();
    
    return response()->json([
        'success' => true,
        'data' => ['ai_active' => $contact->ai_active],
    ]);
}
```

### 5.3 Update contacts API response
`getContacts()` already returns contact data. Since `ai_active` is a column on the model, it will be auto-included in the JSON response.

## AI Conversation Flow (Delivery Mode ON)

```
Customer orders → add_to_cart → get_cart_summary
  ↓
AI: "Mau pickup atau delivery?"
  ↓
Customer: "Delivery"
  ↓ AI calls: set_delivery_type(delivery_type="delivery")
AI: "Alamat pengiriman?"
  ↓
Customer: "Jl. Contoh No. 123"
  ↓ AI calls: set_delivery_type(delivery_type="delivery", address="Jl. Contoh No. 123")
AI: "Ongkir Rp{X}. Ada catatan? (ketik '-' jika tidak)"
  ↓
Customer: "Jangan pakai sambal"
  ↓ AI calls: set_delivery_type(delivery_type="delivery", address="Jl. Contoh No. 123", notes="Jangan pakai sambal")
AI shows full summary with ongkir → "Konfirmasi?"
  ↓
Customer: "Ya" → confirm_order → order created with delivery_type, alamat, ongkir, catatan
```

```
Customer: "Pickup"
  ↓ AI calls: set_delivery_type(delivery_type="pickup")
AI shows summary (no ongkir) + asks notes → "Konfirmasi?"
  ↓
Customer: "Ya" → confirm_order → order created with delivery_type=pickup, ongkir=0
```
